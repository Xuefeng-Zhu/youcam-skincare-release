Where one visible result comes from.

The local skincare guide combines a short self-reported consultation, source-backed education, an ingredient-label check and an optional YouCam cosmetic observation. These kinds of evidence stay separate. No cosmetic score or label comparison establishes diagnosis or product tolerance.

Reference route, not a completed learner tour. This map is prepared from the implemented code. The learner confirmed current-app readiness after the walkthrough, and a brief recap connected their product feedback to the evidence separation shown below. No code exercise or personal reflection is claimed.

Follow “Check this label”

After a supported consultation path, choose a catalog product and use the synthetic test input Glycerin. A documented overlap should appear as a caution. This example does not imply anyone has an allergy.

  2. Decision: public/label-check.mjs

    Find checkLabel and reviewedVocabulary. The function uses reviewed identity/ingredient data and sourced aliases. It has no cosmetic-score or commission input and makes no server request.

  3. Output: public/app.mjs

    Find renderResult and resultCopy. They show documented overlaps, unresolved entries and qualified outcomes using text nodes. No overlap still cannot establish tolerance or suitability.

The other pieces

Consultation and care holds

consultation-ui.mjs gathers answers and renders the guide. evaluateConsultation in consultation.mjs keeps emergency/review/unknown paths ahead of scan or product output. It does not infer disease from text or photos.

Reviewed public content

guidance.json holds educational text/sources. catalog.json holds two exact dated U.S. label snapshots. These static files contain no personal answers.

Optional observation

initializeObservationUI in observation-ui.mjs manages eligibility, consent and explicit modes. Fixture mode sends no photo. Live mode needs an authorized image and deliberate analysis action.

Local boundary → external service

createAppServer in server.mjs applies local request limits. createYouCamAdapter in lib/youcam.mjs performs the authorized provider flow. The key stays server-side; sensitivities/context stay in browser memory.

To change this, start here

  • Label wording: resultCopy/renderResult in public/app.mjs. Preserve uncertainty and tolerance limits.
  • Question flow/summary: public/index.html and showQuestion/renderGuide in public/consultation-ui.mjs.
  • Care behavior: evaluateConsultation and test/consultation.test.mjs. Consequential rule changes need appropriate evidence and review.
  • Product record: public/catalog.json and test/label-check.test.mjs. Review the exact variant/source before changing a snapshot.

A practice to reuse

Turn a limit into a testable invariant. This project keeps cosmetic scores and commercial metadata outside label decisions. In test/label-check.test.mjs, find cosmetic scores and commercial metadata cannot change a label check. It varies those fields and verifies the same result. On another project, separate decision inputs first, then test that unrelated data cannot change the outcome.
