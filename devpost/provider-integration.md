## Contract and controls

The implemented server-only adapter uses Bearer authentication, V2.0 file initialization, signed HTTPS upload without forwarding the API Bearer key, V2.1 `texture` task creation and bounded status polling. The actual sample verified that path once. General provider reliability, medical validity, every entitlement/quota and personal-image acceptance are not established.

Documented controls include explicit disabled/fixture/live modes, consent/action gating, local Host/Origin checks, image/signature/body limits, one active analysis, two starts per minute, deduplicated polling and no automatic duplicate task after uncertain creation. Care holds invalidate scan eligibility/results. Context, routine, care answers and sensitivities are excluded from provider payloads. Fixture output is clearly labeled and sends no photo.

Source references: [quick start](https://docs.perfectcorp.com/develop/quick_start_guide), [skin-analysis contract](https://docs.perfectcorp.com/reference/ai_skin_analysis/v2.1), [unit consumption](https://docs.perfectcorp.com/reference/ai_skin_analysis/section/overview/unit-consumption), [API terms](https://www.makeupar.com/perfectbeauty/youcam/terms-of-service-api).

The notice distinguishes 24-hour result availability from general provider retention up to 30 days. Local clear/forget does not promise provider cancellation or deletion. Further images/analyses require appropriate specific permission and available permitted units.
